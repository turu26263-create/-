# 画像解析(標準装備) 第2版 2026-10-20

## 根っこ
- 見えた物だけを言う。見えない所を想像で埋めない。
- 1回見て終わりにしない。全体 → 細部 → 照らし直し の3回見る。
- 結果は必ず「確定・推測・不明」に分けて出す。
- 根拠のない数字(「精度95%」など)は出さない。

## 見る手順(毎回この順)
1. 全体を見る: 何の画像か(チャート・データ画面・書類・現物の写真など)、向き、明るさ、ぼけ、切れている所。
2. 細部を見る: 小さい文字・数字・表・グラフの目盛りは、切り出して拡大してから読む(作業場ではPythonのPILで切り出し→Readで見る)。暗い・斜めの画像は補正してから読む。
3. 数える・測る: 個数、位置、目盛りから読んだ値。目盛りから読んだ値は「おおよそ」と書く。
4. 照らし直す(2回目): 読んだ数字同士が合うか確かめる(合計と内訳、前後の値、単位、桁)。合わない所だけもう一度切り出して読み直す。
5. 分けて出す:
   - 確定 = はっきり読めた。もう一度読んでも同じ。
   - 推測 = 読めたが自信が薄い(ぼけ・隠れ・目盛りからの読み)。理由を一言添える。
   - 不明 = 読めない。無理に埋めない。「この部分が読めない、こう撮り直せば読める」と書く。
6. 次の一手: 何が普通と違うか、なぜそう判断したか、次に何を確かめればよいかを短く書く。

## 送る前の下ごしらえ(第2版で追加)
- 向き: スマホ写真の回転情報(EXIF)どおりに起こしてから読む。横倒しのまま読ませない。
- 大きさ: 長辺1568px以内のJPEG(画質0.9)にそろえる。これより大きくても読み手側で縮められるだけで、細かさは増えない。HEICなどもここでJPEGに直す。
- 細かい数字が画面の一部だけにある時は、全体の1枚に加えて、その部分を切り出して拡大した1枚も送る。
- 撮影の質を先に測る(目安であって判定ではない):
  - 暗い: 平均の明るさが低い → 「明るい所で撮り直すと読める」
  - 白飛び: 明るい所が一面に飛んでいる → 「画面の映り込みを避け、少し斜めから」
  - ぶれ: 輪郭のくっきり具合が低い → 「両手で止めて撮り直す」
  - 質が悪くても送るのは止めない。結果の横に撮り直しの案内を出す。

## 頼み文と返事の型(全アプリ共通。第2版で追加)
- 頼み文の頭には、必ず共通の決まりを付ける:写っている物だけ読む/推測で埋めない/読めない所は null/各項目に確かさを付ける。
- 返事は「値」と「確かさ」を分けて受け取る。値のJSONに加えて
  - `sure`: 確定の項目名の並び
  - `guess`: 推測の項目名の並び(理由は `note` に)
  - 値が null の項目 = 不明
  - `retake`: 撮り直せば読める所と撮り方(無ければ "")
- 確かさの付いていない返事は、全部「推測」として扱う(確定に格上げしない)。

## 照らし直しの決まり(アプリの中でも同じことをする。第2版で追加)
- AIの返事をそのまま信じない。アプリ側で数字同士を照らす。
- 照らしで食い違いが出たら、その項目だけを名指しして1回だけ読み直させる。2回目でも合わなければ「推測」にして、食い違いの中身を画面に書く。読み直しは1回まで(何度も回さない)。
- 照らしの例:
  - パチスロ: BIG+REG が総回転を超えない、回転数・差枚が桁外れでない、前日と前々日の区別。
  - 競馬の出馬表: 馬番に重複が無い、頭数は18以下、枠番が頭数から決まる並びと合う、オッズが低い順と人気順が合う。

## 複数の画像を比べる時
- 同じ物を同じ向き・大きさにそろえてから比べる。
- 変わった所・増えた所・消えた所を、場所を言って並べる。
- 撮り方の違い(明るさ・角度)による見かけの違いと、本当の違いを分ける。

## 種類別の決まり
### 為替チャートの画像
- 画像から読んだローソクの値は検算用。売買判断の正本はMT4/MT5の実データ(エントリー同期のスキル fx-entry-sync に従う)。
- 線の種類・本数(9・21・遅行スパン20・ボリ帯)は、たくちんの道具(かきこチャート・EA)の設定を先に確かめてから読む。
- 作った画像や解説図を「実測」と言わない。

### パチンコ・スロットのデータ画面(ぱちなみカメラ)
- 回転数・大当たり回数・グラフの山谷を読む。グラフの値は目盛りからの「おおよそ」。
- 総回転(1日の累計)と現在回転(大当たり後)を取り違えない。区別できない時は不明。
- 設定は画像からは決められない。言えるのは確率から見た「可能性」まで。
- 新台で前日の資料が無い(0や空)時は「新台のため読めない」と出す。

### 競馬(せんば馬。第2版で追加)
- 出馬表: 馬名は写っている表記のまま。読めない字を似た馬名で埋めない(推測で馬名を作らない)。
- オッズ・人気・馬体重は時間で変わる。写真の時点の値として扱う。
- パドック: 調子は見えた範囲(踏み込み・首の使い方・毛ヅヤ・腹回り・発汗・落ち着き)だけで判断し、1頭が小さい・隠れている・数コマしか無い時は「推測」。判断できなければ「?」。
- 調子の判断は予想の材料の1つ。勝ち負けを言い切らない。

### 競輪(せんば競輪)
- 出走表は競馬と同じ決まり(車番の重複なし、選手名は写っているまま)。
- 並び予想・ラインは写真に書いてある物だけを読む。書いてなければ不明。

### 書類・表・看板
- 表は行と列をそろえて写す。読めない桝は空けて「不明」と書く。
- 人の名前・住所・番号など個人の情報は、頼まれた用事に要る分だけ扱う。

## 自作アプリに組み込む時
- アプリはClaudeのアーティファクト(ぱちなみカメラ・せんば馬等)なので、画像解析はアーティファクトの「Claudeに聞く」能力でつなぐ。APIキーをHTMLに書かない(書かなくても動く)。
- 流れ: 撮影/写真を選ぶ → 下ごしらえ(向き・大きさ・質の測定) → Claudeに共通の頼み文で解析させる → アプリ側で照らし直し(食い違いだけ1回読み直し) → 「確定・推測・不明」で表示 → 読めない所だけ撮り直しを促す。
- 表示の色分け: 確定=普通の自動の印、推測=黄色の印(手で確かめる合図)、不明=空欄+撮り直しの案内。手で直した所は「手入力」の印に変える。
- 下ごしらえ・共通の決まり・照らしの部品は、全アプリで同じコード(「画像解析 共通部品」)を使う。直す時はそこだけ直せば全部に効く。
- 既存の機能は消さずに足す。組み込んだら、スマホの幅で画面を開いて実際に動くか確かめてから「完了」と言う。

## 照らしの問い(出す前に必ず)
- 見えていない物を言っていないか
- 細かい数字は拡大して読んだか
- 数字同士が合っているか確かめたか
- 確定・推測・不明に分けたか
- 根拠のない%を出していないか
- まだやっていない事を「完了」と書いていないか
