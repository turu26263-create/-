# エントリー同期(リアル価格・EAエントリー照合)MT4/MT5

考え方の根っこは「後出しじゃんけん」のスキル(atodashi-janken-kawase)。こっちはそれを注文に落とす時の決まり。ぶつかったら、売買ルールは後出しじゃんけん・既存EAが正、注文の手順はこっちが正。

## 目的
チャートの確定足、売買シグナル、EAの判断、注文要求、約定結果を、同じ銘柄・同じ足・同じサーバー時刻で追えるようにする。約定価格の完全一致は保証できない(ズレを測って記録するのが仕事)。

## 絶対の決まり
1. 売買ルール(入口・出口の条件)を勝手に変えない。特に売りロジックは触らない。
2. 判断は確定足だけ。新しい足の最初のティックで shift=1 を1回だけ判定する。起動した直後に、過去の足で出ていたシグナルで発注しない。
3. 判定の正本は MT4/MT5 の実OHLCとティック。画像から読んだ値は検算用。生成した画像や解説図を「実測」と呼ばない。
4. MT4とMT5の業者価格は一致するとは限らない。同じ業者・口座・銘柄・時間足・サーバー時刻で照合する。
5. 遅行スパンは今の終値を後ろにずらして描く線。描いてある位置(過去)と、判断した時刻(今の確定足)を取り違えない。ずらす本数・レンジの本数は既存EAとたくちんのチャートの設定から確かめる。確かめられない時は勝手に決めず、そのシグナルは無効にする。
6. 未来1・3・5本の予測は「表示だけ」。入口の合図には使わない(先に出さない=後出しじゃんけん)。
7. 検証の済んでいないロジックで実注文を出さない。インジケーター(表示だけ)とEA(発注する)をはっきり分ける。
8. コンパイルやテストをしていない所は「未検証」と書く。嘘の完了報告をしない。

## 注文の手順(実装契約)
1. 足の鍵は `symbol,timeframe,bar_open_time`。
2. 注文直前に最新ティックとBid/Askを取る。買いはAsk、売りはBidで新規。
   次を調べ、おかしければ新規を止める: `spread_points` `tick_age_ms` `deviation` `stops_level` `freeze_level` `volume_step` `trade_mode` `margin`。
3. 二重発注を防ぐ: `signal_id = symbol|timeframe|bar_open_time|direction|strategy_version` を保存する。再起動しても戻せるように残す(MT4/MT5ならグローバル変数かファイル)。同じ signal_id はもう出さない。
4. 注文が失敗・時間切れの時は、すぐ打ち直さない。まず保有ポジションと注文履歴を見て、通っていないと確かめてから再試行する。
5. 約定の確定: MT5は取引トランザクション(OnTradeTransaction)と履歴で、MT4は OrderSend の結果と履歴で照合する。

## ログに残す項目
`signal_id, bar_open_time, bar_close_time, signal_time, tick_time, decision_time, request_time, fill_time, OHLC, Bid, Ask, spread, requested_price, filled_price, slippage_points, order_id, deal_id, retcode, reason`
- 判定・発注・約定は別々の行(別々の時刻)で残す。
- 異常として記録するもの: 遅延、価格の更新停止、時間足の不一致、スプレッドの急拡大、注文拒否、部分約定。閾値は口座・銘柄ごとに確かめて決める(決め打ちしない)。

## 照らしの問い(書いたら必ず確認)
- 判断値は全部 shift=1 以上か。未来の足を見ていないか。描き直し(リペイント)しないか
- 新しい足で1回だけ判定しているか。起動直後の古いシグナルで撃っていないか
- 同じシグナルで2回撃てないか(再起動後も)
- 買いAsk・売りBidになっているか。スプレッド等の検査で止まるか
- 失敗時に履歴を見てから打ち直しているか
- 遅行スパンの描画位置を判断時刻に使っていないか
- 売買ルールを変えていないか
- 未検証の所を未検証と書いたか

## 土台の型(MT4・たくちん承認の新バー判定)
EAの OnTick はこの形から始める。売買ルールは「ここに接続」の所につなぐだけ。

```mql4
#property strict

datetime lastBar = 0;

void OnTick()
{
   datetime currentBar = iTime(Symbol(), Period(), 0);
   if(currentBar <= 0 || currentBar == lastBar)
      return;

   // EA起動直後は過去の足で発注しない
   if(lastBar == 0)
   {
      lastBar = currentBar;
      return;
   }

   lastBar = currentBar;

   datetime candleTime = iTime(Symbol(), Period(), 1);
   double o = iOpen(Symbol(), Period(), 1);
   double h = iHigh(Symbol(), Period(), 1);
   double l = iLow(Symbol(), Period(), 1);
   double c = iClose(Symbol(), Period(), 1);

   if(candleTime <= 0 || h < l)
      return;

   Print("確定足=", TimeToString(candleTime),
         " O=", DoubleToString(o, Digits),
         " H=", DoubleToString(h, Digits),
         " L=", DoubleToString(l, Digits),
         " C=", DoubleToString(c, Digits),
         " 判定時刻=", TimeToString(TimeCurrent()));

   // ここに既存の売買ルールを接続する
   // 画像認識値との照合は別モジュールで実施
}
```
- この型で守れていること: 新しい足で1回だけ判定、起動直後は撃たない、判断値はshift=1、判定時刻を残す。
- この型にまだ無いもの(注文をつなぐ時に足す): signal_id の保存と再起動後の復元、注文直前のBid/Ask・スプレッド等の検査、発注・約定のログ、失敗時の履歴照合。
- MT5では iTime 等の代わりに CopyRates で同じ形にする(配列は ArraySetAsSeries で [1] が確定足)。

## 試験で通す場面
同じ足で複数ティック、ティック欠落、再起動、約定拒否、リクオート、部分約定、5桁/3桁、夏時間、週明けのギャップ、MT4とMT5のテスターの差。実運用の前にデモで確かめる。

## 進め方
1. 既存EAのコードを読み、入口・出口の条件と遅行スパン・レンジの本数を書き出す(変えない)。
2. 注文の部分だけを、上の手順に置き換える(signal_id、注文前の検査、ログ、失敗時の照合)。
3. コンパイルとチャートへの貼り付けまでやる。できない環境なら未検証と書く。
4. デモで上の試験場面を通し、ログで「判定→発注→約定」の時刻と価格ズレを見る。
5. 数字の評価は温故知新の書と呪文の書を引いてから。検証は3年分、ローソク1本ずつ確かめる(ぶん回し禁止)。

## 資料メモ(2026-10-20の引き継ぎZIP「Claude用・FX資料一式」)
- FX_Forecast_MT4.mq4 / FX_Forecast_MT5.mq5 は予測表示の試作インジケーター。発注しない。RangeBars=20は仮置き。コンパイル・実機検証は未実施。
- 注文の同期・執行コードはまだどのEAにも入っていない(仕様だけ)。
- EA_4棚 v10 / v12 は参考資料。どちらが稼働中の最新版かは未確認。勝手に最新と決めない。
- 「買い矢印が3本早い」という指摘は、原因を既存EAのコード・実OHLC・足時刻で確かめてから直す。機械的に3本遅らせない。
- 9MA/21MAと遅行スパンの条件は元資料と照合する。一目の雲など別のロジックを勝手に足さない。
- 遅行スパンの「一番外」は、21本前の1本の外か、21本全体の外かで数字が大きく変わる。どちらの意味かはたくちんの手の印で決める。
