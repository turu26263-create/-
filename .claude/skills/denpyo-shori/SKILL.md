# 伝票処理_標準装備(2026年11月14日)

状態:【黄】見本の伝票1枚で、写真→文字→取り出し→突き合わせを照らし済み。本物の店のレシートではまだ。

## 芯
- 読み違いは**勝手に直さない**。計算が合わない所は「要確認」に出して、紙を見てもらう
- 数字は必ず2通り以上で突き合わせる(1つの読みだけで信じない)

## 順番
1. 文字にする:写真なら `scripts/ocr_jpn.js`(tesseract.js 5.1.1+日本語辞書を手元から読む。ネット不要。`npm i tesseract.js@5.1.1 @tesseract.js-data/jpn@1.0.0`)。Claude の目で読める時は、目で読んだ物と OCR の両方を比べる(gazou-kaiseki も使う)
2. 取り出す:`python3 scripts/denpyo_yomi.py 文字.txt` → JSON(店・登録番号・日付・時刻・明細・小計・税率別・合計・預り・釣り・要確認)
3. 突き合わせ(道具が自動でやる):
   - 明細の足し算 = 小計
   - 8%対象 + 10%対象 = 合計
   - 税率ごとの消費税 = 対象額 × 8/108 または 10/110(1円未満のずれは許す)
   - ※(軽減税率)の明細の足し算 = 8%対象
   - 預り − 釣り = 合計(合わない時は「預り ○○ の読み違いかも」と出す)
   - 日付・時刻があり得る数字か
   - 登録番号は T+13けた。頭の字が T 以外に読めたら「要確認」
4. 要確認が0になるまで、紙(写真)で確かめてもらう。直した数字は「直した」と書き残す
5. 入れる:家計簿・帳場へ。勘定(食費・日用品・部品など)は明細の品名から案を出し、決めるのはたくちん

## 税・書類の決まり(2026年11月時点。迷ったら税務署・国税庁)
- 適格請求書(インボイス)に要る物:発行する店の名前と登録番号(T+13けた)、取引の日、内容(軽減税率の物はそうと分かる印)、税率ごとの合計と税率、税率ごとの消費税、受け取る人の名前(レシート=簡易インボイスなら省ける)
- 登録番号が無い伝票は仕入税額控除の扱いが変わる → 「登録番号なし」と印をつける
- 領収書の収入印紙(売上代金の受取書):税抜の受取金額が5万円未満は要らない。5万〜100万円 200円、〜200万円 400円、〜300万円 600円、〜500万円 1,000円。消費税が分けて書いてあれば税抜の額で見る。クレジットカード払いと書いた領収書は要らない
- 車検の法定費用(重量税・自賠責・印紙)は消費税がかからない(立替)

## 【照らし済】(11-14)
見本の伝票の写真(少し傾けた・試験用の架空の店)を OCR → 読み違い3つ(T→「、10:23→169:23、2,000→2,006)が出た → 道具が3つとも「要確認」に出した。明細・小計・税率別・消費税の突き合わせは全部合った。見本:`scripts/denpyo_mihon.png`・`scripts/ocr_out.txt`
