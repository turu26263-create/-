# アプリに足して動作確認_標準装備(2026年11月14日・マークファクトリーで作った進め方)

正本:宝物ターンテーブル\2_スキルの皿\アプリに足して動作確認_標準装備_20261114.md(このスキルと同じ中身。食い違ったら正本が正しい)。
状態:【黄】使ったのは1回(マークファクトリー版2、71項目照らして全部OK)。実機の携帯・Claudeアプリの中ではまだ照らしていない。

## 印の意味(混ぜない)
- 【たくちん】=たくちんの言葉そのまま。勝手に変えない
- 【照らし済】=本物のブラウザで確かめた結果(何で確かめたか書く)
- 【未照らし】=まだ確かめていない。「できた」と言わない

## もとの言葉
【たくちん】「マークファクトリーにたして 動作確認」→ 何を足すかは聞いて、4つ全部(請求書・領収書/売上の集計/車の写真/作業予約カレンダー)になった。
【たくちん】(作った後)「これに使ったスキルは？」「スキルパックにして 最初にゆったこと」

## 順番(この順で。飛ばさない)

### 1. 相手を見つける(聞き直さない)
- アーティファクトなら `Artifact action:list scope:all` で名前を引く。リポジトリ・Drive も探す
- `Artifact action:read` で読み、保存されたファイルを**全部の行**読む(読まないまま出し直さない)
- 今の機能・データの入れ物(localStorage の鍵の名前など)・付いている機能(capabilities)を控える

### 2. 足す前に、今の版を照らす(土台の照らし)
- 足す前に壊れていないか見る。後で「元から壊れていた」と区別できる
- 本物のブラウザ(Playwright の Chromium、携帯の幅 390px)で、全部のタブ・ボタンを1回ずつ押す試験を書いて回す
- マークファクトリーでは33項目、全部OK【照らし済】

### 3. 足す物を決める
- 言葉で分かる時は聞かずに進める
- 分からない時だけ、選びやすい案を4つまで出して1回だけ聞く(複数選べる形)。マークファクトリーでは「前のチャットの話がここに無い」ので聞いた
- 聞く前に HANDOFF.md に「今の版は照らし済み、足す物はたくちん待ち」と書いて押し上げる

### 4. 作る前に読むスキル(スキルホスト)
- 必ず:artifact-design(ページの決まり)、artifact-capabilities(AI・保存・カメラの決まり)
- 必ず:**gokansei(互換性)**。Android・iPhone・パソコンで同じに動くか。【たくちん】の決まりで「アプリを作る・直す・公開する時は必ず」。マークファクトリーでは読み忘れた(反省)
- 場合で:gazou-kaiseki(写真・QRを読む時)、setsuyaku・piorimu-kiwami(長い作業)

### 5. 作る時の決まり(アーティファクトの枠で決まっている事)
- 印刷ボタンは動かない(window.print は効かない)→ 書類は「文面をコピー」と画面を写す、にする
- カメラは直接開けない → `<input type="file" accept="image/*" capture="environment">` で「撮る・選ぶ」
- 電話・メールのリンク(tel: sms:)は効かない事がある → 番号を文字で見せ、コピーも付ける
- alert・confirm は出ない → 削除は「2回押しで消す」をページの中で作る
- 外から読む部品は決まったCDNだけ(cdnjs・jsdelivr など)、版を固定する
- 携帯の幅で横にはみ出さない。明るい画面・暗い画面の両方で色を token で決める
- 前のデータを壊さない:新しい入れ物は「無ければ足す」で引き継ぐ(前のお客さんの記録が消えない)
- 見本のデータには「見本」の札を付け、「見本を消す」で一緒に消えるようにする
- 写真など大きい物は localStorage でなく IndexedDB。控え(バックアップ)に入れるかは選べるようにする
- 法律・お金の数字(消費税・印紙など)は、根拠を確かめて書き、「目安・迷ったら税務署」と添える

### 6. 動作確認(数字まで照らす)
- 試験は「押したら何が起きるか」だけでなく**数字が合うか**まで見る(例:見積もり 22,330円、売上 40,600円、粗利 1,800円、印紙 56,800円の振込→200円、カード払い→不要)
- 数字は先に手で計算しておき、試験の答えと比べる
- 本物の部品で試す:QRなら本物のQR画像を作って読ませる、写真なら本物の画像を入れる
- 読み込み直しても残るか(保存)、控えから戻せるかも試す
- 横はみ出し(scrollWidth ≤ 390)と JS のエラー無しを最後に見る
- 試験が途中で止まっても、そこまでの結果は出るようにする(try で包む)
- 見た目は画面写しで**1回だけ**見て、気になった所(例:状態の札が横いっぱいに伸びる)を直す。直したら試験をもう1回回す

### 7. 出す・残す
- 同じURLに出し直す(`url` を付けて publish)。capabilities は書かなければ前のまま
- 出した物・試験の道具を リポジトリ(例 `markfactory/`)に置き、HANDOFF.md に「照らし済み(何で)/まだ」を書いて押し上げる
- 報告は「照らし済み」と「まだ」を分けて書く。実機の携帯で見ていない物は「まだ」

## つまずいた所(次は先に避ける)
- 作業場のネットでは CDN(jsdelivr)に出られない → `npm pack jsqr@1.4.0` で手元に取り、試験の中で CDN の住所を手元のファイルに差し替える(page.route)
- 閉じた「＋」の欄(details)の中は、開いてからでないと入力できない
- 保存すると閉じるフォームに、続けて入力しようとすると止まる(試験の書き方のミス。アプリは正しい)
- グリッドの中の札(chip)は横いっぱいに伸びる → `justify-self:start; width:max-content`
