# バグバグ修正機(2026-11-06/11-07 足の中の線の先読みを足した)

## 1. いつ通すか
- 部品・形・データを足した/直した時、**成績を見る前**に必ず。
- 数字が急に変わった、売りと買いでおかしい、たくちんに「暴走」「アホ買い」と言われた時。
- 修正機が全部○でも、ローソクで1本ずつ照らすのは別に要る(修正機は型のミスを拾うだけ)。

## 2. 使い方
- 研究台:engine/nyu/bugbug.py の bugbug(make, raw, clock, maxpos, spr)。make(mk, d) は向きを受けて玉の表を返す。
- 自分で回す見本:python3 engine/nyu/bugbug.py <MT4 1時間足の置き場> → engine/kekka_tai/nyu/bugbug.txt
- 見るもの:玉の中身(損益が数か・降り>入り・理由の名前・同時玉≤上限・利確で負けない・建値の大負け・入った次の足で合図降り・二重入り)/二度回し/順番/鏡/先読み/ローソクで見る玉。
- × → 成績を見ずに直す。△ → ローソクで見て、作りどおりか書く。

## 3. ミスの型帳(見つけた時 → 拾う照らし)
| 型 | 起きたこと | 拾う照らし |
|---|---|---|
| 列を順番で取る | 降りの合図の代わりに時刻の列を取り「いつも真」(11-06) | 回帰・理由の名前・入った次の足の降り |
| 前から続く合図を新しい合図と読む | 引け先取りで、前からの219で入った次の足に降りた(11-06) | 入った次の足で合図降り 10%以上で× |
| 利確線が入り値の下 | 利確で負けた(11-06) | 利確で負けた玉 |
| 売りのスプレッド | 売りの合図降りでスプレッドをもらっていた・建値/TSの伸びがずれ(11-06) | 鏡 |
| 端数 | ぴったり届いた所で届く/届かないが入れかわる(11-06) | 鏡(1e-9 許す) |
| 買いと売りの数えが同じ名前 | 買いを先に回すと売りが買いの数えを使った(11-06) | 順番 |
| 古いしまい場所 | 足の表を作り直しても前の答えを使った(11-06) | 二度回し・順番 |
| 真偽が数になる | 判定の真偽を数として足した(11-05) | 回帰・ローソク |
| 玉が無い時に根っこを消す | 持っていない時に根っこの線を消した(11-05) | ローソク |
| 先読み | 先の足の値を使う | 先読みなし(途中で切って同じ) |
| 足の中の線の先読み | 利確の4h±3.5σを、いま動いている1時間足が閉じる時の4h足の値で、その1時間足の中で使っていた(11-07。形3 +19,002p → 直すと +10,890p)。途中で切る照らしでは見つからない | 足の中で使う線(利確・網)は1本前の足が閉じた時の値か(test_all)。数字が良すぎる時は真っ先に疑う |
| 部品どうしのつながりが切れている | 売りの降りを変えたのに、ドテン買い(売りの利確で構える)は古い売りの利確から作っていた=幽霊の売り(11-10。「残す」と報告した物が本当は×)。EA の写しとの玉合わせで見つけた | 形を変えたら、それを元に動く部品(ドテン等)にも同じ変更を渡す。決める前に EA の写しと1玉ずつ合わせる |
| 時刻の単位・区切り | pandas の時刻がマイクロ秒/1D の区切りずれ/4hの区切りが業者と違う | ローソクで時刻を照らす・データ合わせ |
| 合図の足の取り違え | 診断で別の足を見ていた(11-06 2017) | エンジンが使った値から取り直す |
| 買いだけ回していた | 売りを入れていないのに「エンジン通り」と言った(11-06) | 買い・売り両方を出す |

## 4. 直し方の順番
1. ×の玉を1つ選び、ローソクで歩く(時刻・値段・9/21・川・合図がわかった時刻)。
2. 原因を1行で書く(どの型か)。新しい型なら型帳に足す。
3. 直す。直した所の近くに日付と1行の理由を書く。
4. わざと壊した形で修正機が×を出すか確かめる(出なければ修正機に型を足す)。
5. test_all を回す。前の数字が変わったら、どの玉がなぜ変わったか言えるまで進まない。新しい期待の数字を足す。
6. HANDOFF.md に「見つけたミス・直した・数字がどう変わった」を書いてプッシュ。たくちんへはミスを隠さず先に言う。

## 5. 嘘をつかない
- 修正機を通していない物は「まだ」。全部○でも「型のミスは無い」までしか言わない。
