## ターボで足した物(11-06)
- 読み込みのしまい場所 load_cached():csv を読んだ物を pickle にしまう(データの置き場の .nyu_cache)。2回目から照らし19個が全部で5秒
- 並べて回す grid_turbo():CPU の数だけ同時に回す(fork で写すので読み直さない)。180通り 3.9秒
- 売買の部品:網(前の日の安値/足の線の5p下、上げるだけ)・利確(足の±kσ)・しあわせセット(lock pips 伸びたら次の足から網を建値へ)。足の中は 網→利確→合図の降り の順(損な方を先)。窓で網を飛び越えたら始値で降りる
- 1玉ずつ 含み損の最大(mae)・伸びた最大(mfe)、成績に 取れた割合%・伸びてから負けた玉・降りの理由(芯/足し/網/利確/建値)

## 改良(11-06 たくちん「エンジンさき 改良は?」)engine/nyu/kairyou_check.py → engine/kekka_tai/nyu/改良の照らし.txt
- cost_adjust():0時(サーバー時刻)に広がるスプレッド・持っている晩のスワップ(水曜は3晩)を足す。付けなければ今と同じ
- nenbetsu():年ごとの損益・負けた年の数・一番悪い年・3年ずつの PF
- montecarlo():山の順番を何千通りに並べ替えて、運が悪い時の DD(95%・99%)。資金とロットで円にもする
- hitotsuzutsu():1個ずつの道具。今の形から部品を1つ外す・変えた時の差と判定(確かめる年が全部下がらない=○・全部下がる=×・ほか=△)

- 精度の極み:Market.hl_order(tf) で、足の中で高値と安値のどちらが先かを元の細かい足(1分足)から作る。run_tai(fine=True) で、同じ足で網と利確の両方に届いた時に先を決める(わからない時は損な方=網)。回数は t.attrs['同じ足で網と利確']
  - HistData で照らした:決まった形は同じ足で両方に届いたことが0回(利確とTSが離れている)。前の日の網でも2回だけ・どちらも網が先 → 1時間足のままで精度は落ちていない
  - 注:HistData(EST)ではロールオーバーは17時。0時のスプレッドの試しは時刻を合わせること

## エントリー調節(11-06 たくちん「10まん2000 レバレッジ33% で エントリ調節きくように」)
- lot_sizing(t, base, d, capital_yen, margin_cap, leverage, step, min_lot, max_lot, maxpos, fixed_lot, compound):入るたびにロットを決めて円で回し直す。持っている玉の証拠金の合計が資金(含み損込み)の margin_cap を超えないよう、残りの枠で割る。足りなければ入らない
- stopout=維持率%(強制決済・ゼロカット)/dd_pips_per_lot+dd_budget=落ち込みで決める(並べ替えの DD95 が資金の dd_budget に収まるロット)
- 返り値:玉ごとのロットと円/最後の資金・増えた倍率・一番へこんだ資金・落ち込み率・証拠金維持率の一番低い・入れなかった合図
